# cctree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 `cctree`：不帶參數就能執行的跨平台 TUI。它把 Claude Code、Codex 帶出的所有 process 整理成可收合的樹，顯示 PID、CPU 與白話記憶體分類，標出失聯的殘留 process，並能安全結束單一 process 或整棵樹。

**Architecture:** 單一 Cargo package。
- `src/lib.rs` 放不依賴 UI 的核心，流程是 collect → classify → tree → kill，全部以可序列化的 `Snapshot` 為輸入。因此辨識邏輯在任何 OS 上都能用合成資料或實機 fixture 做單元測試。
- 平台差異（記憶體 FFI、送訊號）放在 `cfg` 模組裡，並另外提供純函式的數值對應，讓這部分也能在任何 OS 上測試。
- `src/main.rs` 與 `src/ui/` 跑 ratatui 程式：worker 執行緒每 2 秒產生一份 snapshot 並完成分類；UI 執行緒建樹、依 UI 狀態攤平後繪製。

**Tech Stack:**
- Rust edition 2024（作者機器為 rustc 1.98）
- sysinfo 0.39.6
- ratatui 0.30.2（crossterm 一律用 `ratatui::crossterm` 這份 re-export，不另外加 crossterm 依賴）
- serde 1.0.229 + serde_json 1.0.154、toml 1.1.8、unicode-width 0.2.2
- libc 0.2.191（unix）、windows 0.62.2（Windows）
- 測試用：insta 1.49.0、tempfile 3.27.0
- 發佈：dist（cargo-dist）

**Spec:** `docs/superpowers/specs/2026-10-22-cctree-design.md`。章節編號（例如 §4.3）都是指這份文件。

## Global Constraints

- **編譯目標**：`aarch64-apple-darwin`、`x86_64-apple-darwin`、`x86_64-pc-windows-msvc`、`x86_64-unknown-linux-musl`、`aarch64-unknown-linux-musl`。
- **不連網、不寫檔**：執行時不連網、不收集遙測資料；除了隱藏參數 `--dump-snapshot <path>` 的輸出檔，不寫入任何檔案。
- **不需要管理員權限**：讀不到的欄位顯示 `—`，並說明原因。
- **環境變數**：從其他 process 讀取時，只保留 `ENV_ALLOWLIST` 內的名稱，其他值一律不儲存。
- **命令列**：一律經過 `mask_argv` 處理後才顯示，不提供顯示原文的選項。
- **更新間隔**：預設 2 秒，`+`／`-` 可在 1～10 秒之間調整。
- **終端機尺寸**：最小 80×24；不足時改畫「視窗太小」畫面。
- **效能預算**（作者的 Apple silicon Mac、約 1000 個 process、2 秒更新）：
  - cctree 自身 1 分鐘平均 CPU ≤ 單一核心的 2%
  - RSS < 50 MB
  - 單次收集 ≤ 40 ms
- **CPU% 的計算方式**：macOS／Linux 以單一核心為 100%；Windows 以整台機器為 100%。
- **結束 process**：
  - 只確認一次（Enter 確定／Esc 取消）。
  - unix：從最深的子孫開始送 SIGTERM，最多等 3 秒，還沒結束的送 SIGKILL。
  - Windows：從最深的子孫開始用 TerminateProcess 直接結束。
- **介面語言**：`zh_TW`／`zh_HK`／`zh_Hant*` 顯示繁體中文，其他顯示英文；`CCTREE_LANG` 可強制指定；有設定 `NO_COLOR` 時不使用顏色。
- **錯誤訊息格式**：發生什麼事 → 影響什麼 → 怎麼解決。
- **README 與授權**：README 必須寫明「非官方，與 Anthropic、OpenAI 無關」；授權為 `MIT OR Apache-2.0`。
- **Commit 訊息**：最後一行固定是 `Claude-Session: https://claude.ai/code/session_01Nj9nmvDCeM84cmxsMz17NH`。

## Review Focus

1. **process 在列舉後、讀取細節前就結束**：該列顯示 `—`，下一次更新時消失，程式不會 panic。由 Task 3 `read_mem_of_exited_pid_reports_gone` 與 Task 6 `collector_tolerates_vanished_process` 測試。
2. **Windows 上舊的或被重用的 PPID 形成循環**：建立 lineage 時要能結束，並把循環中的 process 視為被收養。由 Task 8 `lineage_breaks_ppid_cycles` 測試。
3. **cctree 本身就跑在某個 Claude Code session 裡**（例如透過它的 Bash 工具）：在那個 session 上按 `X` 要被擋下（SelfOrAncestor），在其他列按 `x` 仍然正常。由 Task 16 `tree_kill_refused_when_it_contains_cctree_ancestor` 測試。
4. **`~/.claude.json` 壞掉或很大**（有對話紀錄時可達數 MB）：MCP 改用套件名稱命名，只顯示一則設定檔問題訊息，不會當掉；檔案修改時間沒變就不重新解析。由 Task 9 `malformed_claude_json_is_a_problem_not_a_panic`、`loader_skips_reparse_when_mtime_unchanged` 測試。
5. **80 欄寬的終端機搭配很長的中文路徑與 MCP 名稱**：欄位維持對齊，名稱依顯示寬度截斷並加上 `…`。由 Task 19 snapshot `render_80x24_long_cjk_labels` 測試。

- [ ] **Step 3：實作。**
  - 三個 `from_*` 函式依 §4.4 的表格對應各欄位。
    - `shared` 的算法：macOS 是 `resident − internal`，Windows 是 `working_set − private_ws`，一律用 `saturating_sub`。

  - **`execute` 的流程**：
    1. 先對每個目標呼叫 `state()`：`Gone` 計入 `already_gone`，`Reused` 計入 `skipped_reused`。
